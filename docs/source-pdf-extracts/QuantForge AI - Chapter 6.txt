6.1 Purpose
This chapter defines the physical PostgreSQL database architecture for QuantForge AI.
The database is designed to support:
Historical market data
Quantitative research
Strategy discovery
Backtesting
Validation

Risk management
Reporting
Administration
The design emphasizes:
High performance
Data integrity
Scalability
Auditability
Maintainability
6.2 Database Architecture
QuantForge AI uses PostgreSQL as the primary data store.
The platform separates logical workloads into dedicated schemas.

6.3 Why Schemas Instead of Separate Databases?
Version 1 uses one PostgreSQL cluster with multiple schemas.
Advantages
Single backup strategy
Easier joins
Simpler administration
Lower operational complexity
Easier local development
Future versions can move schemas to dedicated databases if required.

6.7 Primary Key Strategy
Every business entity shall use UUID as its primary key.
Example
idUUIDPRIMARYKEY
Reasons
Globally unique
Easy replication
Easier future microservices
Safer imports
No sequence conflicts
6.8 Foreign Key Strategy
Every relationship shall use explicit foreign keys.
Example
strategy_version
        │
        ▼
strategy
Foreign keys shall always be indexed.

6.26 Database Design Rules
Raw OHLCV is immutable.
Indicators are not permanently stored by default.
Every entity has one owner .
Every table has audit fields.
UUID is the standard primary key.
UTC timestamps only.
Financial values use NUMERIC.
JSONB only for metadata.
Large tables are partitioned.
Critical actions are transactional and auditable.
